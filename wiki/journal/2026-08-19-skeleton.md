## 목표
- 한 명령으로 뜨는 실험 환경: coupon-api(실험용 엔드포인트) + mock-external + Postgres/Redis/Toxiproxy + Prometheus/Grafana (docker compose, 리소스 제한 S/M/L)
- k6 smoke/baseline 시나리오와 `scripts/run-experiment.sh`로 E1(계측 검증)까지 통과

## 범위 / 하지 않는 것
- 쿠폰 도메인(엔티티/전략)은 3주차. 이번엔 DB 연결 확인용 `/api/db/ping`까지만.
- Grafana 대시보드는 최소 패널(RPS, p99, in-flight, JVM, Hikari)만.

## 진행 기록 (시간순)
- 시작: 환경 확인 (docker 데몬, brew, start.spring.io 접근)
- Docker 데몬 꺼져 있음 → `open -a Docker`로 기동 (27.5.1). brew 있음, start.spring.io 접근 OK.
- **Initializr가 Spring Boot 3.x를 더 이상 제공하지 않음** (제공: 4.1.0, 4.0.7). 계획서의 3.3.x는 EOL → **Boot 4.0.7(안정 패치 라인) + Gradle 9.5.1**로 결정 → [D-004](../decisions/D-004-spring-boot-4.md). Boot 4 차이점: 스타터명 `spring-boot-starter-webmvc`(구 `-web`), 테스트 스타터 분리(`-webmvc-test`, `-data-jpa-test`…), Flyway는 `spring-boot-starter-flyway`, Testcontainers 2.x 아티팩트(`testcontainers-postgresql`).
- 두 앱(coupon-api, mock-external)을 Initializr로 생성 → 루트 멀티프로젝트로 재배치 (wrapper 1개, 플러그인 버전은 `settings.gradle` pluginManagement).
- 백그라운드로 Gradle 배포판 다운로드 + `brew install k6` (→ k6 v2.1.0 설치됨).
- coupon-api 작성: `application.yml`(VT/POOL_SIZE/TOMCAT_MAX_THREADS/EXTERNAL_* 전부 env 주입), 실험 엔드포인트 7종(`ExperimentController`), in-flight 게이지 필터(`http_inflight_requests{group}`), `RestClient`(JDK HttpClient, connect/read 타임아웃, read=0이면 무제한), 외부 실패→502/504 매핑, Flyway V1(coupon/coupon_issue 스키마), Dockerfile(호스트 빌드 jar 복사).
  - pinning 엔드포인트 설계 포인트: 요청마다 다른 락(4096 stripes)을 써서 "락 경합"이 아니라 "pinning"만 보이게. 요청 로컬 `new Object()`는 JIT 락 제거 가능성이 있어 피함.
- mock-external 작성: `/notify`(지연/실패율 파라미터 > 전역 fault), `/admin/fault`(GET/POST 부분갱신/reset), 모드 normal|slow|error|hang|flapping, `mock_notify_total{outcome}` 카운터.
- `./gradlew bootJar -x test` **첫 빌드 성공** (컴파일 에러 0).
- docker-compose.yml: postgres(max_connections env)/redis/mock-external/toxiproxy(18081→mock)/coupon-api(APP_CPUS/APP_MEM/APP_JAVA_OPTS)/prometheus v3.5.0(remote-write receiver)/grafana 11.6.0(익명 Admin, 프로비저닝).
- 모니터링: prometheus.yml(5s scrape), Grafana 대시보드 JSON 13패널(RPS/p99/percentiles/에러율/in-flight/threads/CPU/heap/GC/Hikari/mock outcome/k6 rate/k6 latency), `testid` 변수로 k6 실험 필터.
- k6: `lib/config.js`(open-model 헬퍼), 00-smoke, 10-baseline-ping, 20-io-sleep, 21-io-external, 30-cpu-bound, 60-breakpoint(abortOnFail).
  - k6 v2.1.0 확인: `-o experimental-prometheus-rw`, `--summary-export` 여전히 사용 가능 (`prometheus-rw`는 없음).
- scripts: `build.sh`(jar+이미지), `run-experiment.sh`(프로파일→APP_CPUS/MEM/Xmx 매핑, compose up, health 대기, docker stats 샘플러, k6 remote-write+summary, summarize), `summarize.py`(summary.json+stats → 표 한 줄 `summary.md`).
- compose up 완료 (7개 컨테이너 모두 Up, postgres/redis healthy). health UP(db/redis 포함), 실험 엔드포인트 7종 전부 200.
- k6 smoke(00-smoke.js, 20s): 210/210 checks 통과.
- `run-experiment.sh` 전체 파이프라인 점검(`E1-pipeline-check`, ping 2,000rps): summary.md 생성, Prometheus에 k6 지표(remote-write)와 서버 지표 모두 확인, Grafana 대시보드 프로비저닝·렌더링 확인(브라우저로 직접 봄).
  - 수정: 샘플러 kill 시 `Terminated` 메시지 → `{ kill && wait; } 2>/dev/null`; dropped 메트릭 부재 시 0 표기; k6 duration은 초 단위 → 대시보드 단위 `s`; 범례를 list 모드로 축소.
- E1 베이스라인(`E1-M-vt-ping`, 500→6,000rps): 평균 3,611rps, 서버 피크 6,000rps, p99 88ms, CPU 97% → [E1](../experiments/E1-baseline.md).
